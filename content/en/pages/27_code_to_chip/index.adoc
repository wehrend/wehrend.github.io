==== First attempt: it does not fit

// - Synthesize the CPU from chapter 26 unchanged -> results table (about 4000 of 1280 logic cells, >300 %).

==== Making the memories fit

// - Register file in block RAM: synchronous read, two copies (bank1, bank2) for two read ports.
// - First idea: read on the FALLING edge -> CPU stays single-cycle (half a period for reading,
//   half for ALU + write back). Fits: 832 logic cells. But timing: Fmax 15.2 MHz -> nextpnr
//   "FAIL at 25.00 MHz" and ERROR. Good real-world example for step 4!
// - Solution: read on the RISING edge (regfile.v). Works because of the clock enable:
//   one instruction needs ce = 1 plus at least one more clock edge to read the operands
//   -> ce must never be 1 in two cycles in a row (CE_DIV >= 2).
//   Strictly speaking, the CPU is no longer single-cycle - small teaser for part 4.
// - Data memory: 8 words instead of 64 (stays in flip-flops: 256 SB_DFFE).
//   Alternative: data memory in block RAM too, lw in two cycles.
// - Results table (all measured):
//     chapter 26 unchanged:               ~4000 of 1280 logic cells (>300 %), does not fit
//     regfile BRAM, read on falling edge:   832 (65 %), Fmax 15.2 MHz, FAIL at 25 MHz
//     regfile BRAM, read on rising edge:    839 (65 %), 4 block RAMs, Fmax 30.3 MHz, PASS
// - Lesson: Verilog for simulation is not yet Verilog for a specific chip.
//   Describe memories the way the tool can map them to block RAM (check: SB_RAM40_4K in `make stat`).

==== Clock, reset and output

// - Clock enable instead of a divided clock: everything runs on 25 MHz on the global clock network,
//   ce = 1 for one cycle every CE_DIV cycles (CE_DIV = 6,250,000 -> 4 instructions per second).
//   Why a divided clock from a counter bit is a bad idea on an FPGA (not on the clock network, skew).
// - Reset: power-on reset (first 15 cycles) + button 1 with synchronizer (two flip-flops,
//   metastability -> chapter 11/12). Bouncing does not matter for a reset.
// - Output: lowest byte of x1 as two hex digits on the 7-segment displays (decoder from chapter 23,
//   inverted: the Go Board's segments are active low), instruction number PC/4 on the LEDs.
// - Debug output: dbg_x1 is a copy of x1, updated on every write to x1 - the contents of a
//   block RAM cannot be watched from outside, and hierarchical names do not exist in hardware.
// - Testbench go_board_top_tb.v with CE_DIV = 4: one line per instruction, checks "0A" on the display.
