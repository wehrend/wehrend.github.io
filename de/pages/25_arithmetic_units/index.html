      Rechenwerke

      In diesem Kapitel steigen wir tiefer in den Kaninchenbau hinab und sehen uns an, wie Multiplikation und Division ganzer Zahlen in Hardware umgesetzt werden:

      Schieben und Barrel-Shifter

      Note
      Warum >>> und nicht >>?

      Verilog hat zwei Operatoren für das Rechtsschieben:

      • >> ist der logische Shift: Er schiebt immer Nullen nach. 8’b11011001 >> 1 ergibt 8’b01101100.

      • >>> ist der arithmetische Shift: Er schiebt Kopien des Vorzeichenbits nach, aber nur, wenn der Wert vorzeichenbehaftet ist. $signed(8’b11011001) >>> 1 ergibt 8’b11101100, also -20.

      Bei einem vorzeichenlosen Wert verhält sich >>> genau wie >>. Deshalb muss der Wert als vorzeichenbehaftet gekennzeichnet werden, entweder mit $signed() oder durch die Deklaration als reg signed bzw. wire signed.

      In C und Java ist >> bei einer vorzeichenbehafteten Zahl meist ebenfalls ein arithmetischer Shift. Verilog macht den Unterschied ausdrücklich. Für das Linksschieben gibt es auch <<<, es tut aber genau dasselbe wie <<.

      Important
      Warum gibt es kein arithmetisches Linksschieben (sla)?

      Der Unterschied zwischen „logisch“ und „arithmetisch“ liegt allein darin, was in die frei werdende Stelle nachgeschoben wird.

      Beim Rechtsschieben wird links eine Stelle frei, also dort, wo das Vorzeichenbit sitzt. Es gibt zwei sinnvolle Möglichkeiten: Nullen für vorzeichenlose Zahlen (srl) oder Kopien des Vorzeichenbits für vorzeichenbehaftete Zahlen (sra).

      Beim Linksschieben wird rechts eine Stelle frei, beim niederwertigsten Bit. Dort ist eine 0 immer richtig, egal ob die Zahl ein Vorzeichen hat oder nicht. Auch im Zweierkomplement bedeutet „mal 2“ einfach „alles eine Stelle nach links, rechts eine 0“:

       -3 = 11111101   << 1  =  11111010 = -6
  5 = 00000101   << 1  =  00001010 = 10

      Ein sla würde also genau dieselben Bits liefern wie sll. Es wäre nur ein zweiter Name für dieselbe Operation.

      Passt das Ergebnis nicht mehr in den Zahlenbereich, kippt das Vorzeichen:

      100 = 01100100   << 1  =  11001000 = -56   (statt 200)

      Das ist ein Überlauf, genau wie bei add. Das Vorzeichenbit festzuhalten würde auch nicht helfen: 200 passt schlicht nicht in 8 Bit mit Vorzeichen.

      Der Barrel-Shifter

      Was wäre, wenn wir Hardware hätten, die Bits um eine beliebige Anzahl von Stellen nach links oder rechts schiebt?

      Genau das tut ein Barrel-Shifter; seine Funktionsweise erklären wir unten Befehl für Befehl…​

      Ein Barrel-Shifter kann die Bits um den Betrag von shamt schieben, also um 1, 2, 4 oder eine Kombination dieser Beträge.

      // srl: shift right logical, 8 bit. Zeros are shifted in from the left.
module shifter_srl (
    input  wire [7:0] a,
    input  wire [2:0] shamt,
    output wire [7:0] y
);
    wire [7:0] s1, s2;

    assign s1 = shamt[0] ? {1'b0,    a[7:1]}  : a;    // shift by 1 or not
    assign s2 = shamt[1] ? {2'b00,   s1[7:2]} : s1;   // shift by 2 or not
    assign y  = shamt[2] ? {4'b0000, s2[7:4]} : s2;   // shift by 4 or not
endmodule

      // sra: shift right arithmetic, 8 bit. Copies of the sign bit a[7] are shifted in from the left.
module shifter_sra (
    input  wire [7:0] a,
    input  wire [2:0] shamt,
    output wire [7:0] y
);
    wire [7:0] s1, s2;

    assign s1 = shamt[0] ? {a[7],      a[7:1]}  : a;    // shift by 1 or not
    assign s2 = shamt[1] ? {{2{a[7]}}, s1[7:2]} : s1;   // shift by 2 or not
    assign y  = shamt[2] ? {{4{a[7]}}, s2[7:4]} : s2;   // shift by 4 or not
endmodule

      // sll: shift left logical, 8 bit. Zeros are shifted in from the right.
module shifter_sll (
    input  wire [7:0] a,
    input  wire [2:0] shamt,
    output wire [7:0] y
);
    wire [7:0] s1, s2;

    assign s1 = shamt[0] ? {a[6:0],  1'b0}    : a;    // shift by 1 or not
    assign s2 = shamt[1] ? {s1[5:0], 2'b00}   : s1;   // shift by 2 or not
    assign y  = shamt[2] ? {s2[3:0], 4'b0000} : s2;   // shift by 4 or not
endmodule

      // All three shifts in one circuit: sll, srl and sra, 8 bit.
//   op = 00: sll (shift left logical)
//   op = 01: srl (shift right logical)
//   op = 11: sra (shift right arithmetic)
// The three stages always shift to the right. A left shift is done by
// reversing the bit order before and after shifting.
module shifter_all (
    input  wire [7:0] a,
    input  wire [2:0] shamt,
    input  wire [1:0] op,
    output wire [7:0] y
);
    wire left = (op == 2'b00);          // sll
    wire fill = op[1] & a[7];           // sra: sign bit, sll/srl: 0

    // reverse the bit order for sll: a[0] becomes bit 7, a[7] becomes bit 0
    wire [7:0] a_rev = {a[0], a[1], a[2], a[3], a[4], a[5], a[6], a[7]};
    wire [7:0] in    = left ? a_rev : a;

    // the three shift stages, always to the right
    wire [7:0] s1, s2, s3;
    assign s1 = shamt[0] ? {fill,      in[7:1]} : in;   // shift by 1 or not
    assign s2 = shamt[1] ? {{2{fill}}, s1[7:2]} : s1;   // shift by 2 or not
    assign s3 = shamt[2] ? {{4{fill}}, s2[7:4]} : s2;   // shift by 4 or not

    // reverse back after shifting
    wire [7:0] s3_rev = {s3[0], s3[1], s3[2], s3[3], s3[4], s3[5], s3[6], s3[7]};
    assign y = left ? s3_rev : s3;
endmodule

      `timescale 1ns / 1ps

// Tests the three single-purpose shifters and the combined shifter against the Verilog operators.
module shifters_tb;
    reg  [7:0] a;
    reg  [2:0] shamt;
    wire [7:0] y_sll, y_srl, y_sra;
    wire [7:0] all_sll, all_srl, all_sra;
    reg  [7:0] exp_sll, exp_srl, exp_sra;
    integer i, j, errors = 0;

    shifter_sll u_sll (.a(a), .shamt(shamt), .y(y_sll));
    shifter_srl u_srl (.a(a), .shamt(shamt), .y(y_srl));
    shifter_sra u_sra (.a(a), .shamt(shamt), .y(y_sra));

    // the combined shifter, once for every operation
    shifter_all u_all_sll (.a(a), .shamt(shamt), .op(2'b00), .y(all_sll));
    shifter_all u_all_srl (.a(a), .shamt(shamt), .op(2'b01), .y(all_srl));
    shifter_all u_all_sra (.a(a), .shamt(shamt), .op(2'b11), .y(all_sra));

    initial begin
        a = 8'b1001_0110; shamt = 3; #1;
        $display("a = %b, shamt = 3:  sll = %b  srl = %b  sra = %b", a, y_sll, y_srl, y_sra);

        for (i = 0; i < 256; i = i + 1)
            for (j = 0; j < 8; j = j + 1) begin
                a = i; shamt = j; #1;
                // compute the expected values first: inside a comparison with an unsigned
                // signal, $signed(a) >>> shamt would be evaluated unsigned (and shift in zeros)
                exp_sll = a << shamt;
                exp_srl = a >> shamt;
                exp_sra = $signed(a) >>> shamt;
                if (y_sll !== exp_sll || y_srl !== exp_srl || y_sra !== exp_sra
                    || all_sll !== exp_sll || all_srl !== exp_srl || all_sra !== exp_sra) begin
                    errors = errors + 1;
                    $display("ERROR: a=%b shamt=%0d", a, shamt);
                end
            end
        if (errors == 0) $display("PASSED: all 2048 combinations correct for sll, srl, sra and the combined shifter");
        else             $display("FAILED: %0d errors", errors);
        $finish;
    end
endmodule

      Zuerst gibt sie ein Beispiel zum Nachlesen aus: a = 10010110 um 3 geschoben ergibt 10110000 bei sll, 00010010 bei srl und 11110010 bei sra.

      Dann geht sie alle möglichen Eingaben durch: alle 256 Werte von a und alle 8 Schiebeweiten, insgesamt 2048 Kombinationen. Für jede davon vergleicht sie die Ausgänge mit dem Ergebnis der Verilog-Operatoren <<, >> und >>>. Stimmen alle Ausgänge überein, meldet die Testbench PASSED. Weil jede Kombination getestet wird, bedeutet PASSED, dass die Schaltungen für jede Eingabe korrekt sind, nicht nur für ein paar Beispiele.

      Warning
      Eine Falle in der Testbench

      Die erwarteten Werte werden zuerst in eigenen Registern gespeichert (exp_sll, exp_srl, exp_sra) und erst dann verglichen. Das sieht überflüssig aus, ist es aber nicht. Bei einem Vergleich wie

      y_sra !== $signed(a) >>> shamt

      wertet Verilog den ganzen Ausdruck vorzeichenlos aus, weil y_sra vorzeichenlos ist. Dann schiebt >>> Nullen statt des Vorzeichenbits nach, und die Testbench meldet bei jeder negativen Zahl Fehler, obwohl die Schaltung richtig ist. Schreibt man $signed(a) >>> shamt zuerst in ein eigenes Register, lässt sich das vermeiden.

      Multiplizierer

      Die Multiplikation mit einer Zweierpotenz ist ein einziger Shift. Aber jede Zahl ist eine Summe von Zweierpotenzen, also ist jede Multiplikation eine Summe von Shifts:

      \[ x \cdot 10 = x \cdot (8 + 2) = (x \ll 3) + (x \ll 1) \]

      Das ist die Grundidee aller Multiplizierer: Für jedes Bit des Multiplikators, das 1 ist, wird der Multiplikand an die Stelle dieses Bits geschoben und addiert.

      Schriftliche Multiplikation

      Die binäre Multiplikation funktioniert genau wie die schriftliche Multiplikation aus der Schule, nur einfacher. Jedes Bit des Multiplikators b ergibt eine Zeile, ein Teilprodukt: Ist das Bit 1, ist die Zeile der Multiplikand a, ist es 0, besteht die Zeile nur aus Nullen. Jede Zeile ist eine Stelle weiter nach links verschoben. Am Ende werden alle Zeilen addiert.

      Im Binärsystem ist ein Teilprodukt nichts anderes als ein AND: Jedes Bit von a wird mit einem Bit von b verundet. Und das Ergebnis braucht doppelt so viele Bits wie die Eingaben: 4 Bit mal 4 Bit ergibt bis zu 8 Bit, denn 15 · 15 = 225.

      Array-Multiplizierer

      Der Array-Multiplizierer baut die schriftliche Multiplikation direkt in Hardware nach: eine Reihe von AND-Gattern für jedes Bit von b und ein Addierer für jede Zeile nach der ersten. Als Addierer verwenden wir den Ripple-Carry-Addierer aus Kapitel 23 (ripple_adder.v und full_adder.v), mit dem Parameter N auf die Breite des Multiplizierers gesetzt.

      Das Bild folgt unserem Beispiel 13 · 11. In jeder Zeile ist das unterste Bit der Summe bereits endgültig: Es ändert sich nicht mehr, weil alle folgenden Zeilen weiter nach links verschoben sind. Es verlässt das Array also als ein Bit des Produkts (p0 bis p3), und nur die übrigen Bits wandern zusammen mit dem Übertrag in die nächste Zeile. Nach der letzten Zeile bilden diese übrigen Bits die obere Hälfte des Produkts.

      // N x N array multiplier (unsigned), purely combinational.
// Like long multiplication on paper: every bit of b selects a partial product
// (a AND b[i]), and one ripple-carry adder per row adds it to the running sum.
module array_multiplier #(
    parameter N = 4
) (
    input  wire [N-1:0]   a,
    input  wire [N-1:0]   b,
    output wire [2*N-1:0] p
);
    // partial products: row i = a AND b[i]
    wire [N-1:0] pp [0:N-1];
    // running sum after each row (upper N bits, the lowest bit is already final)
    wire [N-1:0] acc [0:N-1];

    genvar i;
    generate
        for (i = 0; i < N; i = i + 1) begin : partial
            assign pp[i] = a & {N{b[i]}};
        end

        // row 0: nothing to add yet, bit 0 of the product is final
        assign p[0]   = pp[0][0];
        assign acc[0] = {1'b0, pp[0][N-1:1]};

        // rows 1 .. N-1: one adder per row
        for (i = 1; i < N; i = i + 1) begin : row
            wire [N-1:0] sum;
            wire         cout;
            ripple_adder #(.N(N)) add (
                .a(acc[i-1]), .b(pp[i]), .cin(1'b0),
                .sum(sum), .cout(cout)
            );
            assign p[i]   = sum[0];                 // lowest bit is final
            assign acc[i] = {cout, sum[N-1:1]};     // the rest moves on to the next row
        end
    endgenerate

    // after the last row, the remaining bits are the upper half of the product
    assign p[2*N-1:N] = acc[N-1];
endmodule

      Der Verilog-Code beschreibt diese Struktur mit zwei generate-Schleifen: Die erste erzeugt die Teilprodukte pp[i] = a & {N{b[i]}}, die zweite einen Addierer pro Zeile. Da der Code nur beschreibt, wie die Zeilen verbunden sind, funktioniert dasselbe Modul für jedes N.

      Die Testbench gibt unser Beispiel aus (13 · 11 = 143) und vergleicht dann alle 256 Kombinationen zweier 4-Bit-Zahlen mit dem Verilog-Operator *. Stimmen alle überein, meldet sie PASSED.

      Der Array-Multiplizierer liefert das Ergebnis innerhalb eines Taktes, hat aber zwei Nachteile. Erstens wächst seine Größe mit dem Quadrat von N: N Zeilen mit je N AND-Gattern und N−1 Addierer. Yosys synthetisiert die 4-Bit-Version zu 64 Zellen, die 8-Bit-Version schon zu 327. Eine 32-Bit-Version wäre riesig. Zweitens müssen die Signale nacheinander durch alle Addierer laufen. Dieser lange Pfad begrenzt die Taktfrequenz.

      Sequentieller Multiplizierer

      Der sequentielle Multiplizierer löst das Größenproblem andersherum: Statt N Addierer nebeneinander verwendet er einen einzigen Addierer N-mal, ein Bit des Multiplikators pro Takt.

      Der Trick ist das Produktregister. Seine obere Hälfte enthält die laufende Summe, seine untere Hälfte die Bits des Multiplikators, die noch nicht verarbeitet sind. In jedem Takt passieren zwei Dinge:

      1. Ist das unterste Bit prod[0] gleich 1, wird der Multiplikand zur oberen Hälfte addiert.

      2. Dann wird das ganze Register um ein Bit nach rechts geschoben.

      Das Schieben bringt das nächste Multiplikator-Bit an Position 0 und schiebt gleichzeitig das unterste fertige Bit des Produkts in die untere Hälfte. Nach N Takten sind alle Bits des Multiplikators verbraucht, und das Register enthält das vollständige Produkt. Die obere Hälfte hat ein zusätzliches Bit, weil die Addition einen Übertrag erzeugen kann.

      // Sequential shift-and-add multiplier (unsigned), one bit per clock cycle.
// Needs only one N-bit adder instead of N-1 adders, but takes N clock cycles.
//
// The product register holds the upper half (running sum) and the lower half
// (the remaining multiplier bits) at the same time: in every cycle
//   1. if the lowest bit is 1, the multiplicand is added to the upper half,
//   2. the whole register is shifted right by one bit.
// After N cycles the register contains the complete product.
module seq_multiplier #(
    parameter N = 8
) (
    input  wire           clk,
    input  wire           rst,
    input  wire           start,    // one clock cycle high: start a multiplication
    input  wire [N-1:0]   a,        // multiplicand
    input  wire [N-1:0]   b,        // multiplier
    output wire [2*N-1:0] p,        // product
    output reg            busy,
    output reg            done      // high when p is valid, until the next start
);
    reg [N-1:0] mcand;                  // multiplicand, stays constant
    reg [2*N:0] prod;                   // one extra bit for the carry of the addition
    reg [$clog2(N+1)-1:0] count;        // remaining steps

    wire [N:0] upper = prod[2*N:N] + (prod[0] ? {1'b0, mcand} : {(N+1){1'b0}});

    always @(posedge clk) begin
        if (rst) begin
            busy  <= 0;
            done  <= 0;
            count <= 0;
            prod  <= 0;
            mcand <= 0;
        end else if (start && !busy) begin
            mcand <= a;
            prod  <= {{(N+1){1'b0}}, b};   // upper half 0, lower half = multiplier
            count <= N;
            busy  <= 1;
            done  <= 0;
        end else if (busy) begin
            prod  <= {upper, prod[N-1:0]} >> 1;   // add, then shift right
            count <= count - 1;
            if (count == 1) begin
                busy <= 0;
                done <= 1;
            end
        end
    end

    assign p = prod[2*N-1:0];
endmodule

      Hier kommt die sequentielle Logik aus Kapitel 24 ins Spiel. Ein Impuls auf start lädt den Multiplikanden, legt den Multiplikator in die untere Hälfte und setzt einen Zähler auf N. Solange busy 1 ist, addiert und schiebt die Schaltung in jedem Takt und zählt herunter. Ist der Zähler abgelaufen, geht done auf 1, und das Produkt p ist gültig.

      `timescale 1ns / 1ps

module seq_multiplier_tb;
    reg         clk = 0;
    reg         rst = 1;
    reg         start = 0;
    reg  [7:0]  a = 0, b = 0;
    wire [15:0] p;
    wire        busy, done;
    integer i, j, errors = 0, tests = 0;

    seq_multiplier #(.N(8)) dut (
        .clk(clk), .rst(rst), .start(start), .a(a), .b(b),
        .p(p), .busy(busy), .done(done)
    );

    // for the waveform: the two halves of the product register
    wire [7:0] upper = dut.prod[15:8];    // running sum
    wire [7:0] lower = dut.prod[7:0];     // remaining multiplier bits (and the finished product bits)

    // clock: period 10 ns
    always #5 clk = ~clk;

    // start one multiplication and wait until it is done
    task multiply(input [7:0] x, input [7:0] y);
        begin
            @(negedge clk);           // change inputs away from the rising edge
            a = x; b = y; start = 1;
            @(negedge clk);
            start = 0;
            @(posedge done);
            @(negedge clk);
            tests = tests + 1;
            if (p !== x * y) begin
                errors = errors + 1;
                $display("ERROR: %0d * %0d = %0d, expected %0d", x, y, p, x * y);
            end
        end
    endtask

    initial begin
        $dumpfile("seq_multiplier.vcd");
        $dumpvars(0, seq_multiplier_tb);
        #12 rst = 0;

        multiply(13, 11);
        $display("t=%0d ns  13 * 11 = %0d", $time, p);

        #20 $dumpoff;                 // the exhaustive test would make the file huge
        for (i = 0; i < 256; i = i + 1)
            for (j = 0; j < 256; j = j + 1)
                multiply(i, j);

        if (errors == 0) $display("PASSED: %0d products correct", tests);
        else             $display("FAILED: %0d of %0d", errors, tests);
        $finish;
    end
endmodule

      Die Testbench verwendet einen task, um eine Multiplikation zu starten und auf done zu warten. Sie rechnet zuerst unser Beispiel und dann alle 65.536 Kombinationen zweier 8-Bit-Zahlen, was ein paar Sekunden dauert. Für die Waveform zeigt sie die beiden Hälften des Produktregisters als die Signale upper und lower.

      Die Waveform zeigt die Multiplikation 13 · 11 mit b = 00001011. Bei 25 ns lädt start das Register, und der Zähler beginnt bei 8. Ab 35 ns folgt mit jeder Taktflanke ein Schritt.       Das ist ein Grundprinzip des Hardware-Entwurfs: Fläche lässt sich gegen Zeit tauschen. Der Barrel-Shifter war eine Schaltung nach dem Prinzip „alles auf einmal“, der sequentielle Multiplizierer ist die erste nach dem Prinzip „Schritt für Schritt“. Echte CPUs verwenden schnellere Verfahren wie Booth-Kodierung, Wallace-Bäume oder Pipelining, aber sie alle bauen auf diesen beiden Ideen auf.

      Note
      Und vorzeichenbehaftete Zahlen?

      Beide Multiplizierer arbeiten mit vorzeichenlosen Zahlen. Interessanterweise sind die unteren N Bits des Produkts bei vorzeichenbehafteten und vorzeichenlosen Zahlen gleich. Deshalb hat RISC-V für die untere Hälfte nur einen Befehl mul. Nur die obere Hälfte unterscheidet sich, daher gibt es für sie drei Befehle: mulh (mit Vorzeichen · mit Vorzeichen), mulhu (ohne Vorzeichen · ohne Vorzeichen) und mulhsu (mit Vorzeichen · ohne Vorzeichen).

      Dividierer

      Die Division ist die Umkehrung der Multiplikation: Statt zu schieben und zu addieren, schieben und subtrahieren wir.

      Schriftliche Division

      Wieder beginnen wir mit dem Verfahren aus der Schule. Man nimmt so viele Stellen des Dividenden, bis der Divisor hineinpasst, schreibt eine 1 in den Quotienten, zieht den Divisor ab und holt die nächste Stelle herunter. Passt der Divisor nicht, schreibt man eine 0 und holt einfach die nächste Stelle herunter.

      Im Binärsystem ist das noch einfacher als im Dezimalsystem: Der Divisor passt entweder einmal oder gar nicht. Man muss also nicht raten, wie oft er passt. Jeder Schritt ist nur ein Vergleich und eine Subtraktion, und jedes Quotientenbit ist entweder 1 oder 0. In unserem Beispiel ergibt 1100100 (100) geteilt durch 111 (7) den Quotienten 1110 (14) mit dem Rest 10 (2).

      Sequentieller Dividierer

      Der sequentielle Dividierer führt genau diese Schritte aus, ein Quotientenbit pro Takt. Er braucht drei Register: den Divisor, der konstant bleibt, den Rest, der bei 0 beginnt, und das Quotientenregister, das mit dem Dividenden beginnt. In jedem Takt:

      1. Das nächste Bit des Dividenden, das MSB des Quotientenregisters, wird von rechts in den Rest geschoben. Das ist das „Herunterholen der nächsten Stelle“.

      2. Der Divisor wird von diesem geschobenen Wert abgezogen. Gibt es kein Borgen, ist die Differenz nicht negativ: Der Divisor passt. Dann wird die Differenz zum neuen Rest. Passt er nicht, behält der Rest seinen alten Wert, er wird „wiederhergestellt“. Daher heißt dieses Verfahren Restoring Division.

      3. Das Quotientenregister wird nach links geschoben, und das Ergebnis des Vergleichs, fits, wird sein neues unterstes Bit.

      Das Quotientenregister erfüllt also zwei Aufgaben gleichzeitig: Links werden die Bits des Dividenden hinausgeschoben, rechts die Bits des Quotienten hineingeschoben. Nach N Takten sind alle Bits des Dividenden verbraucht, und das Register enthält den vollständigen Quotienten. Das Restregister enthält den Rest.

      // Sequential restoring divider (unsigned), one quotient bit per clock cycle.
// Works like long division on paper: in every cycle, the next bit of the
// dividend is shifted into the remainder, and the divisor is subtracted if it fits.
//   - fits (no borrow):  remainder = difference, quotient bit = 1
//   - does not fit:      remainder stays (is "restored"), quotient bit = 0
// After N cycles: quotient = dividend / divisor, remainder = dividend % divisor.
//
// Division by zero needs no special case: the divisor 0 always "fits",
// so the quotient becomes all ones and the remainder equals the dividend.
// This is exactly what RISC-V specifies for divu/remu.
module seq_divider #(
    parameter N = 8
) (
    input  wire         clk,
    input  wire         rst,
    input  wire         start,      // one clock cycle high: start a division
    input  wire [N-1:0] dividend,
    input  wire [N-1:0] divisor,
    output reg  [N-1:0] quotient,
    output reg  [N-1:0] remainder,
    output reg          busy,
    output reg          done        // high when the results are valid, until the next start
);
    reg [N-1:0] dsor;                   // divisor, stays constant
    reg [$clog2(N+1)-1:0] count;        // remaining steps

    // shift the next dividend bit (MSB of the quotient register) into the remainder
    wire [N:0] shifted = {remainder, quotient[N-1]};
    wire [N:0] diff    = shifted - {1'b0, dsor};
    wire       fits    = !diff[N];      // no borrow: divisor fits

    always @(posedge clk) begin
        if (rst) begin
            busy      <= 0;
            done      <= 0;
            count     <= 0;
            quotient  <= 0;
            remainder <= 0;
            dsor      <= 0;
        end else if (start && !busy) begin
            dsor      <= divisor;
            quotient  <= dividend;      // the quotient register starts with the dividend
            remainder <= 0;
            count     <= N;
            busy      <= 1;
            done      <= 0;
        end else if (busy) begin
            remainder <= fits ? diff[N-1:0] : shifted[N-1:0];
            quotient  <= {quotient[N-2:0], fits};
            count     <= count - 1;
            if (count == 1) begin
                busy <= 0;
                done <= 1;
            end
        end
    end
endmodule

      Die Steuerung ist dieselbe wie beim sequentiellen Multiplizierer: start lädt die Register und setzt den Zähler auf N, busy ist 1, solange die Schaltung arbeitet, und done zeigt an, dass Quotient und Rest gültig sind. Die Subtraktion verwendet N+1 Bits, damit das Borgen im obersten Bit diff[N] erscheint: Ist es 0, passt der Divisor.

      `timescale 1ns / 1ps

module seq_divider_tb;
    reg        clk = 0;
    reg        rst = 1;
    reg        start = 0;
    reg  [7:0] dividend = 0, divisor = 0;
    wire [7:0] quotient, remainder;
    wire       busy, done;
    reg  [7:0] exp_q, exp_r;
    integer i, j, errors = 0, tests = 0;

    seq_divider #(.N(8)) dut (
        .clk(clk), .rst(rst), .start(start),
        .dividend(dividend), .divisor(divisor),
        .quotient(quotient), .remainder(remainder),
        .busy(busy), .done(done)
    );

    // clock: period 10 ns
    always #5 clk = ~clk;

    // start one division and wait until it is done
    task divide(input [7:0] x, input [7:0] y);
        begin
            @(negedge clk);
            dividend = x; divisor = y; start = 1;
            @(negedge clk);
            start = 0;
            @(posedge done);
            @(negedge clk);
            // division by zero: RISC-V defines quotient = all ones, remainder = dividend
            exp_q = (y == 0) ? 8'hFF : x / y;
            exp_r = (y == 0) ? x     : x % y;
            tests = tests + 1;
            if (quotient !== exp_q || remainder !== exp_r) begin
                errors = errors + 1;
                $display("ERROR: %0d / %0d = %0d rest %0d, expected %0d rest %0d",
                         x, y, quotient, remainder, exp_q, exp_r);
            end
        end
    endtask

    initial begin
        $dumpfile("seq_divider.vcd");
        $dumpvars(0, seq_divider_tb);
        #12 rst = 0;

        divide(100, 7);
        $display("t=%0d ns  100 / 7 = %0d rest %0d", $time, quotient, remainder);
        divide(42, 0);
        $display("t=%0d ns  42 / 0 = %0d rest %0d", $time, quotient, remainder);

        $dumpoff;                     // the exhaustive test would make the file huge
        for (i = 0; i < 256; i = i + 1)
            for (j = 0; j < 256; j = j + 1)
                divide(i, j);

        if (errors == 0) $display("PASSED: %0d divisions correct", tests);
        else             $display("FAILED: %0d of %0d", errors, tests);
        $finish;
    end
endmodule

      Die Testbench teilt zuerst 100 durch 7 und 42 durch 0 und prüft dann alle 65.536 Kombinationen zweier 8-Bit-Zahlen gegen die Verilog-Operatoren / und %.

      Die Waveform zeigt die Division 100 : 7. Bei 25 ns lädt start das Quotientenregister mit dem Dividenden 01100100. Ab 35 ns folgt mit jeder Taktflanke ein Schritt. In den ersten vier Schritten wächst der Rest auf 0, 1, 3 und 6, während die Bits des Dividenden hineinwandern, aber 7 passt nie, also sind die Quotientenbits 0. Im fünften Schritt, bei 75 ns, wäre der Rest 12: Der Divisor passt, der Rest wird 12 − 7 = 5, und eine 1 wandert in das Quotientenregister. Nach 8 Schritten, bei 105 ns, geht done auf 1: Das Quotientenregister enthält 00001110 (14), der Rest ist 2.

      Note
      Division durch null

      Was passiert, wenn der Divisor 0 ist? Die Schaltung braucht dafür keinen Sonderfall: 0 „passt“ immer, also wird jedes Quotientenbit 1, und vom Rest wird nie etwas abgezogen. Das Ergebnis ist ein Quotient aus lauter Einsen (255) und der Dividend als Rest, 42 : 0 ergibt also 255 Rest 42.

      Genau das schreibt RISC-V für die Befehle divu und remu vor: Eine Division durch null löst keine Ausnahme aus, der Quotient besteht aus lauter Einsen, und der Rest ist der Dividend. Das Programm muss selbst prüfen, ob der Divisor null ist.

      Division mit Vorzeichen

      Unser Dividierer arbeitet nur mit vorzeichenlosen Zahlen. Bei vorzeichenbehafteten Zahlen teilt eine CPU meist die Beträge und korrigiert danach das Vorzeichen. Zwei Details sind wissenswert:

      • Rundung: Das div von RISC-V rundet zur Null hin, wie C: −7 / 2 = −3, mit dem Rest −1. Der arithmetische Shift vom Anfang dieses Kapitels rundet dagegen ab: −7 >>> 1 = −4. Bei negativen Zahlen ist eine Division durch 2 also nicht dasselbe wie ein arithmetischer Rechtsshift.

      • Überlauf: Die kleinste Zahl geteilt durch −1 passt nicht: In 8 Bit wäre −128 / −1 gleich +128. RISC-V legt das Ergebnis als −128 fest, mit dem Rest 0.

      Echte Prozessoren treffen dieselbe Abwägung:

      • Der Arm Cortex-M0+, ein kleiner Mikrocontroller-Kern, kann mit jeder unserer beiden Arten von Multiplizierer gebaut werden: mit einem Multiplizierer, der einen Takt braucht, oder mit einem, der 32 Takte braucht und dafür weniger Fläche benötigt. Der Chip-Designer entscheidet.

      • Der Cortex-M0+ hat überhaupt keinen Divisionsbefehl. Der RP2040 hat deshalb neben jedem seiner beiden Kerne einen Dividierer, der für eine 32-Bit-Division 8 Takte braucht.

      • Ein Desktop-Prozessor wie Intels Skylake multipliziert zwei 64-Bit-Zahlen mit einer Latenz von 3 Takten. Eine 64-Bit-Division dauert je nach Werten zwischen etwa 35 und 89 Takten.

      Note
      		Die Multiplikation ist überall schnell geworden, die Division nicht. Den Grund sieht man an unseren Schaltungen: Die Teilprodukte einer Multiplikation sind alle voneinander unabhängig, sie lassen sich also gleichzeitig berechnen und in einem Baum addieren. Bei einer Division braucht jeder Schritt den Rest des vorherigen Schritts: Ob der Divisor passt, lässt sich erst entscheiden, wenn die vorherige Subtraktion fertig ist. Schnelle Dividierer berechnen mehrere Bits pro Takt, aber nicht alle Bits auf einmal. Deshalb ersetzen Compiler eine Division durch eine Konstante, wo immer es geht, durch eine Multiplikation, und deshalb ist der Shift vom Anfang dieses Kapitels noch immer der schnellste Weg, durch eine Zweierpotenz zu teilen.
